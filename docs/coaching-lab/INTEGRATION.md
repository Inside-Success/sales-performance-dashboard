# Production integration boundary

This branch is an isolated evaluation. Its report is intentionally not accepted by the production v2 validator. A successful isolated report does not bypass production safety or authorize release.

## Layers and ownership

1. Coaching principles: what makes a lesson useful and when an alternative is justified.
2. Definitions: buyer concern, rep response, handling, resolution, payment, and a transferable lesson are different concepts.
3. Offer knowledge: source-linked show/stage facts and commercial rules; effective dates must be explicit where known. Missing historical authority cannot become a retrospective violation.
4. Agent duties: generation and independent substantive review use the same source record, not a lossy handoff summary.
5. Report contract: a focus points to an existing entry. Objection teaching is not copied into a second improvement section. Distinct lessons follow next steps.
6. Presentation: deterministic rendering of the exact reviewed object, with internal identifiers removed from visible prose.

The lab saves each input layer with a source/revision/digest and verifies exact bytes. Private content remains private. Manifest identity changes when any layer changes. Re-running an existing request reuses its saved receipt; a different prompt is a new paid request, never an invisible replacement.

## Required adapters before any production trial

- `src/lib/objection-coaching.cjs`: introduce an explicitly versioned contract and renderer alongside v2. Do not rename v2 arrays in place. Old reports must continue to render unchanged. Current v2 forbids recommendations for sound handling; the new teaching field deliberately allows useful positive teaching without calling it a defect.
- `scripts/coaching-upgrade/stages.cjs`: bind source identity, request identity, policy digest and evidence to the candidate; require a consistent reviewer verdict and explicit eligibility adjudication. Preserve exact reviewed-object rendering and the final safety binding.
- `scripts/coaching-upgrade/repair-contract.cjs` and safety paths: enumerate every new user-visible field, including teaching and hypothetical examples. Whole-field atomic repairs may edit prose only. They may not change source identity, category, payment, evidence or focus ownership. Carry forward November 5 per-candidate adjudication.
- Manual and official presentation: adapt the shared read model to the new object once, rather than reconstructing a report from legacy summaries. Verify both authenticated views, report chat boundaries and enhanced/legacy labels. Never expose diagnostic metadata to reps.
- OpenAI transport: the inspected production provider currently has Anthropic and DeepSeek branches only. Terra/Luna used a separate direct OpenAI transport in this lab. Production would need an OpenAI branch behind the existing claim, receipt, completion and failure boundaries; do not substitute an uncheckpointed HTTP call. Exercise cached reuse, timeout reconciliation and malformed-output repair before activation.
- Durable transport and delivery: retain exact-request checkpoints, current-owner leases, bounded repair, outage backoff, uncertain-delivery holds and named artifact receipts. No extra provider calls are necessary in the normal two-stage coaching path; existing safety/repair responsibilities remain separate.
- Scoring/compliance/usage: keep their schemas, permissions and delivery accounting unchanged. Any mapping needed by a consumer must have explicit compatibility coverage, not inferred field equivalence.

## Acceptance sequence after separate authorization

Offline schema/repair and historical rendering regressions; isolated official/manual workflow replay with real sources and no publishers; authenticated preview review; then a bounded live canary with exact delivery receipts and rollback prepared. Broader activation follows only if output quality and delivery evidence support it. No test can promise zero future failures or prove sales uplift without subsequent rep-use evidence.
